# AGENTS.md — dsh-web-review (webview panel + element annotation)

Rules for the dsh-web-review plugin: the webui's right-side page-preview panel, in-iframe element selection and commenting, and the AI collaboration loop that turns annotations into workspace source edits.

**This plugin lives OUTSIDE the harness checkout** — it is developed in the user's own repo (dsh-web-review) and loaded into a `dsh web` instance by a launch overlay, with zero modifications to the deepseek-harness source tree. Resolve the active harness root with `scripts/harness-path.ts` (or `DSH_HARNESS`), then read `<harness>/packages/client/AGENTS.md`, `<harness>/.agents/notes/implemented/architecture/2026-07-22-slot-type-chain-implementation.md`, and `<harness>/AGENTS.md` before touching slots, stores, or inject faces. Relative links to an assumed sibling checkout are forbidden because they resolve incorrectly from Codex worktrees.

## Harness compatibility baseline

- The reviewed runtime baseline is the `snapshot-20260810T155924Z-8ec407cd64` tag. A harness update is a contract migration, not a blind rebuild: compare the upstream client rules, manifest scanner, Web profile CLI, agent events, and Context renderer before declaring compatibility.
- The 0810 client manifest shape is nested `dsh.client`; `dshClient` is legacy and ignored. Cross-package slot contributions use `ctx.slots.inject(slotName, callback)`. Annotation injection uses the `agent/pre-step` waterfall and appends its sourced user message only to an `enter` decision; `reject` is preserved unchanged.
- The Web profile accepts external launch patches through `--patch`. Do not restore `--config`, direct execution of `apps/cli/src/bin.ts`, `agent/prompt-submit`, `PromptDecision`, or `additionalContexts` from older snapshots.
- Development and E2E launch the resolved checkout's `bin/dsh`, so the CLI uses the harness's own dependency graph and generated runtime. `scripts/harness-path.ts` resolves `DSH_HARNESS` first, then the installed runtime link, then an absolute `link:` dependency in the plugin manifest; failure must be explicit.

## Loading model (why the entry name is an absolute path)

- `dsh web` boots the `web` profile's ordered bundle layers and applies each `--patch` file after the profile/user layers. The Loader and client-modules resolve package names from the profile composition anchor, which does not contain this external checkout.
- An external package is therefore reachable ONLY through an **absolute-path entry name**: both the Loader's `internal.import` and `require.resolve(<name>/package.json)` treat absolute paths as self-resolving, independent of baseUrl. Relative names, workspace: deps, and nested includes all fail somewhere in this chain — do not "simplify" the absolute path.
- The entry name points at the package **directory**, and the package root carries a thin `index.ts` re-export (`export * from './lib/index.js'`): Node/tsx ESM has no directory resolution, and the loader's resolver tries `<dir>/index.<ext>` — without the root entry the load fails with `ERR_MODULE_NOT_FOUND` on `index.json`. The directory form is what keeps `require.resolve(<name>/package.json)` (client-modules' manifest scan) working — a file-path entry would break that scan.
- The launch overlay (`cordis.yml`) inserts one row: `- insert: - { id: dsh-web-review, name: <absolute path to this package> }`. The **tsdown client-bundle banner id must equal the entry name** (`__ModuleLoader__.load({ id: ... })` is checked against the boot-graph row id by `arrive()`); the tsdown config reads it from the generated `packages/dsh-web-review/entry-name.json` (single source shared with `cordis.yml` via `pnpm gen-config`).
- **Official profile-bundle publication is separate from the source-checkout dev channel.** `lib/client.js` keeps the generated absolute-path id required by the external `--patch` development overlay. The same source builds `lib/client-official.js` with the stable package id `@dsh-external/dsh-web-review`; `pnpm package:official` stages that artifact in a prebuilt tarball whose manifest declares `dsh.bundle.patch`. Do not reuse one client artifact for both ids.
- The generated `dist/package/` allowlist is exact: package manifest, `cordis.patch.yml`, self-contained `lib/index.js`, `lib/client-official.js` plus its map, the root README, and its two screenshot assets. Source, `.git`, `node_modules`, machine-local links, generated absolute-path configuration, and the development-channel client bundle must never enter the official package.
- The built node half must stay **self-contained**: the Loader imports the external package from its own directory, which must not require a local `node_modules`. Small DSH construction helpers (`createUserMessage`, `SessionId`) may be value-imported in source only when tsdown inlines them into `lib/index.js`; a surviving bare runtime import is a load-order regression.
- HMR: the repo's `pnpm run dev:web` watch scans only harness `packages/*/*`; the external bundle is watched by the package's OWN tsdown watch (`pnpm run dev:watch`). `dsh web --dev` host polls the bundle files it serves and broadcasts rebuilt frames regardless of who rewrote them.

## Repository conventions

- **The whole repo is TypeScript** — scripts/, demo/, tests/, and the package root's `index.ts` included. `scripts/*.ts` and `demo/server.ts` run via tsx (`pnpm dev`, `pnpm demo`, `pnpm gen-config`); they are typechecked by the `tsconfig.scripts.json` project in the solution. The one deliberate exemption: `packages/dsh-web-review/index.ts` (the Loader's directory-import forwarding entry) is NOT part of any tsc program — it references the tsdown output (`lib/index.js`) which has no declarations; its correctness is pinned by the real-loading test in `tests/entry-load.spec.ts` instead.
- **Generated files are gitignored**: `cordis.yml` and `packages/dsh-web-review/entry-name.json` are produced by `pnpm gen-config` (machine-specific absolute paths — committing them would mislead every other checkout). `dist/` is rebuilt by `pnpm package:official`. `lib/`, `dist/`, `*.tsbuildinfo`, `.env*`, `*.log`, `coverage/`, `test-results/`, `playwright-report/`, `.artifacts/` are also ignored. A commit must not add them; `pnpm check` fails if gen-config would change the files or if the official package allowlist drifts.
- **Pre-commit hook** (zero-dependency, `core.hooksPath` → `scripts/git-hooks`, installed by the `prepare` script on `pnpm install`): runs the fast gate — `tsc -b --force`, `vitest run`, and gen-config idempotence. The e2e browser suite is deliberately NOT in the commit gate (it spawns services and needs a provider key); run `pnpm test:e2e` for UI changes.
- **Quality gate**: `pnpm check` (all gates) / `pnpm check --e2e` (plus the browser suite). Gate list: typecheck, unit suite, gen-config idempotence, current `dsh.client` manifest shape, both channel banner-id contracts, directory-import entry presence, tsdown build, official `dsh.bundle` manifest, and exact package staging allowlist. Pre-commit runs the fast subset.
- The repo is a git repository; commit messages follow the convention of the first commit.

## Scope and ownership

- **One dual-face package.** The node half (`src/index.ts`) hosts the `/webview-proxy` route, the `/webview-annotations` pending-snapshot route, the stable Preview capability system-prompt section, and one `agent/pre-step` listener that appends a separate plugin message to an entered message batch without rewriting the claimed messages; the browser half (`src/client/`) is the preview tab UI, assistant-link delegation, picker injection, annotation store, and acknowledged dock sync. The node half is NOT a generic fetch gateway.
- **Plugin export shape:** named exports `name` / `inject` / `Config` (when present) / `apply`, no default export — a default export makes the Loader discard the namespace (upstream postmortem 0001).
- **The preview is a `conversation.view` tab** (`id: 'webview'`, label 网页预览/Web Preview, order 20, review-panel style) and the annotation strip is a **`conversation.input.dock` entry** (`id: 'webview-annotations'`, order 15, GoalBar style) — both registering the SAME apply-constructed store handle (`store: webviewStore` from `createWebviewStore()`, the ui-conversation chatStore multi-registration pattern: a `StoreHandle` in the `store` seat is shared per scope, a `StoreFactory` would instantiate per entry). The harness shell (ui-layout) is NOT modified: no new slot, no column changes. Both roots carry `data-webview-ui`.
- Cross-plugin panel control goes through the plugin's own store and the `ctx.layout` service only where already offered (`closeDetails`); nothing reaches into another package's store or registers into a slot it did not declare.
- **Product copy is Chinese; code comments, JSDoc, and this file are English** (upstream convention). Locale files contain UI copy only. The locale-independent model context template is pinned in node-owned `annotation-context.ts`, never assembled by components.

## Proxy contract (`/webview-proxy`)

- **Request shape:** `GET /webview-proxy/<path-encoded target>` — the target URL is percent-encoded with `/` kept raw (`encodeTarget`), NOT a query parameter: a query-string base would break relative resolution through the injected `<base>` (relative references replace the base's query). Unparseable or non-http(s) targets → 400. Server-side `fetch` with redirect-follow, ~15s timeout, 10MB response cap. No browser cookies: login-gated pages are the direct mode's job, not the proxy's.
- **HTML responses:** strip `content-security-policy`, `content-security-policy-report-only`, `x-frame-options`; inject `<base href="/webview-proxy/<path-encoded page directory>/">` as the first `<head>` child (this makes every relative URL in the document — including script `fetch('x')` — resolve through the proxy); rewrite absolute AND root-relative http(s) URLs in `href | src | action | srcset | poster | data-src` attributes (single- and double-quoted forms) to proxy URLs (root-relative refs do NOT resolve against `<base>` paths, so they must be rewritten); leave `javascript:` / `mailto:` / `data:` / `tel:` / `blob:` / `file:` / `#` / `?` / plain-relative values untouched. `<form action>` is rewritten for GET and POST; POST forwards the body. `Accept: text/html` navigation to any proxied path fetches the target URL verbatim, so an SPA dev server's fallback serves its index.html through the proxy.
- **Non-HTML responses** (js/css/images) pass through with the target's content-type, no rewriting beyond the CSP/XFO strip.
- **All rewriting lives in pure functions** in `rewrite.ts`: `(html, targetUrl, proxyPrefix) => string` (plus the URL-rewrite helper). The route handler is a thin shell: parse, fetch, branch, stream. No regex-over-HTML anywhere else, no mutable rewrite state, no shared caches.
- **SSRF guard:** only http(s) targets are fetchable; no allowlist-less localhost exemptions without a real consumer need.

## Picker contract (same-origin injection)

- **Same-origin detection:** `try { iframe.contentDocument }` — the iframe is same-origin exactly when it loaded through the proxy. No other signal.
- **Injection:** one `<style>` (hover/selection outlines, pick-mode cursor, marker styles) plus one `<script>` evaluated in the iframe document, both authored as template-literal strings in `src/client/picker.ts` — no build-time asset pipeline, no `postMessage`. The script registers `window.__dshWebviewPicker = { activate, deactivate, isActive, onPick, onCancel, onMarkClick, syncMarkers, select, clearSelection }`; the parent drives it with direct cross-frame function references (same-origin). The rich editor never enters the page DOM: it is a host React overlay, so page opacity, transforms, fonts, and stacking contexts cannot affect it.
- **Picker behavior:** hover highlights the deepest element under the pointer; in pick mode a click on an unannotated element hands it to `onPick` (the parent opens the host editor); a click on an already-annotated element or its marker hands the pick id to `onMarkClick` (re-open that editor). Clicks never navigate (`preventDefault`). The numbered marker circles are the only injected chrome and reposition on scroll/resize. Esc with no editor transaction or a second toggle deactivates pick mode.
- **cssPath:** delegated to `css-selector-generator` (runtime dependency, inlined into the client bundle) with the priority `['id', 'class', 'tag', 'nthoftype']` — order is priority, output is the shortest unique selector, so index segments appear only when uniqueness requires them; `null` falls back to the bare tag. The picker script itself is event-only and never embeds DOM-traversal logic.
- **Snapshot fields** (exact keys, mapped to the wire shape by `annotation-snapshot.ts`): `tagName`, `id`, `className`, `cssPath` (shortest unique selector — runtime anchor for marker rebuilds), `fullPath` (complete ancestor chain), `label` (accessible label), `role` (explicit/implicit ARIA role), `stableClasses` (semantic classes; utility/hashed/variant tokens filtered), `anchor` (framework source anchor or null), `outerHTML` (≤1500 chars), `textContent` (≤300 chars), `rect`, computed `display/position/font-size/color/background-color/margin/padding/width/height`. Caps are contract — enforce at capture and at the node wire boundary, and test exact limits. The source anchor comes from `source-anchor.ts`: framework-agnostic probing of React fiber `_debugSource`, Vue `__file`, and Svelte `__svelte_meta` (defensive reads, null in production builds/unknown frameworks).
- **The page always loads through the proxy** — there is no direct/cross-origin mode, so element picking is always available (login-gated pages simply cannot be annotated; see Known limitations).

## Annotation message and AI collaboration

- **Structured wire, node-owned text.** The browser POSTs `{ sessionId, page, comments[] }`, never XML/Markdown. Each comment carries bounded `changes[]`, optional `textChange`, and edit-time `viewport`; only changed values cross the boundary. `annotation-contract.ts` pins request/count/field/context caps; `annotation-context.ts` strictly validates the shared property allowlist and is the single assembly point. Malformed, oversized, duplicate, wrong-content-type, and unknown-session requests fail visibly.
- **Stable Browser Comments format.** The context is English regardless of UI locale and starts with `# Browser comments`. Each full snapshot says it supersedes earlier snapshots. Page/target/original-value metadata is explicitly untrusted page evidence; comments, requested values, and text replacements are user-authored input. The optional `Browser annotation` block includes viewport plus `property: before -> after` lines. Raw outerHTML, full computed styles, rectangles, editor state, and screenshots are excluded.
- **Send-time context path.** The node face resolves the live branded `SessionId` and stores one deduplicated pending full snapshot. Its `agent/pre-step` listener delegates with `next()`, preserves `reject`, and on `enter` appends one user-role message with `{ kind: 'plugin', plugin: 'dsh-web-review' }` after the returned messages; it never rewrites claimed message content. The exact plugin `user/message` session event consumes the matching pending snapshot, so a rejected/aborted admission cannot lose it and a newer concurrent snapshot cannot be cleared by an older event. Clearing before send removes pending state and injects nothing; `agent/disposed` releases state.
- **Stock input machine remains authoritative for drafts.** Annotation mode adds a dedicated Send button, enabled only after a non-empty snapshot is acknowledged. With a non-blank composer draft it calls the public `inputActions.submit()` action, so ordinary serialization, queueing, failure handling, and successful draft clearing remain stock behavior; the plugin never reads or sends a second copy of that text. The durable human-message node is the success acknowledgement that exits annotation mode and clears the dock. The stock machine deliberately rejects an empty draft, so the no-draft arm calls the scoped public `conversation.send` with the localized fixed request (“请根据页面批注修改前端实现。”); attempting to bypass the machine with an empty text message is forbidden. Failures keep annotations visible and retryable. The stock composer Send remains available and unchanged.
- **No model-facing tool is added:** the context is a logged user-role plugin message; the model acts with existing workspace tools (`tool-fs`, bash). Adding a tool requires a consumer that proves the message form insufficient.
- The AI's workspace is the session's workspace root — the dev instance is launched with `cwd` = the user's project directory (or the GUI workspace picker), so `tool-fs` edits land in the project the iframe previews.

## UI discipline

- Follow the four props shares, the store-factory rule, and the data-access ladder (upstream client rules): business state (url, picks, comments, pick mode, panel open/width/split) lives in `createWebviewStore()` declared at register. Components receive everything through props — no ctx, no React contexts, no hand-made hooks.
- **Assistant-link delegation:** the always-mounted annotation dock owns one document capture-phase listener, including while it renders no capsule. It intercepts only unmodified left-clicks on absolute HTTP(S) anchors inside Harness 0810's `[data-chat-flow-kind="assistant-step"]`; user/tool links, modifier/middle clicks, and `[data-webview-ui]` chrome keep their normal behavior. The injected dock callback normalizes the URL, writes it through the plugin store actions, clears stale picks, closes Details through `ctx.layout`, and activates the registered Preview tab through its accessible tab control. No other package's store is read or mutated.
- **Model guidance:** the node face contributes the reviewed, locale-independent `plugin:dsh-web-review-preview` system section at order `-97`. It states only the capability and review loop: verify a development server, emit an absolute HTTP(S) Markdown link, and let the user annotate the opened Preview page. Keep this stable text in `preview-guidance.ts` and pin it in a real composition test.
- The preview has two chrome states. Browse mode is the URL row with an inline external-open action plus separate refresh and comment-bubble actions. Annotation mode replaces it with the light-blue toolbar: exit, clear, centered current URL, and the counted Send button. The selected element gets a solid-white host editor: collapsed comment pill first, then an Adjust-triggered Figma-style inspector for the shared visual-property allowlist and safe direct-text editing. Changed rows expose individual reset actions. The composer dock renders ONE compact capsule (count + sync state + clear), not one chip per pick. Hover or focus opens a light detail card above it; row click re-opens the same host editor.
- Live element references and rollback ledgers live in component refs (`pickRefs`, `patchRefs`), never in the store. Before the first temporary preview write, record the exact inline value and priority; text edits are limited to one direct text node. Reset, Cancel, remove, clear, successful send, navigation, and unmount must restore the exact original DOM state. Remaining picks re-anchor by cssPath and replay committed preview values after frame reload.

## Known limitations (do not "fix" into breakage)

- **The proxied iframe is not a security boundary.** Arbitrary proxied scripts execute same-origin with the host because the picker uses direct cross-frame references. Structured route validation protects the model-text boundary, not host routes. Complete isolation requires a dedicated proxy origin plus a validated `postMessage` bridge; until then preview only trusted development pages.
- **Annotation preparation and stock-composer Send are not atomic.** The public browser input service has no general pre-submit transaction. The capsule exposes preparing/ready/error; users must wait for “发送时注入”. The pre-step waterfall appends one separately sourced message only after delegating to `next()` and receiving `enter`; claimed-message rewriting and delay-based race hiding remain forbidden.
- **Absolute URLs hardcoded in page JS** (e.g. `fetch('http://host/api')`, `new WebSocket(...)`) are not rewritten; root-relative (`/api`) and relative calls work through `<base>`. Fixing this by executing/rewriting page JS, or by adding a headless browser, is a product decision with real consumer demand — not a bug fix.
- **Dev-server HMR websockets** do not survive the proxy; the page renders but live-reload is absent.
- **Server-side fetch carries no browser cookies** — login-gated pages cannot be annotated (element picking requires the same-origin proxy; there is no direct-mode fallback anymore).
- **The absolute-path entry name is machine-specific**: the yaml and the tsdown banner id must both name this checkout's path. Moving the repo requires regenerating both (`pnpm run gen-config`).
- These are documented for users in the package README (Known Limitations section) and in panel hints; changing them needs a consumer-driven design.

## Testing

- **Pure-function suites** for `rewrite.ts` (attribute forms, base injection, non-HTML pass-through, exact caps) and picker helpers (cssPath, snapshot truncation) — node env for the node half; `// @vitest-environment jsdom` pragma for browser halves.
- **One REAL-composition test for the node half** (upstream rule, docs/testing.md): boot a test-only `cordis.yml` through the Loader with the webserver and this package, serve a fixture page from a local http server, and assert the proxy route returns the rewritten HTML.
- **A real-loading test for the external entry** (`tests/entry-load.spec.ts`): imports the package directory in a tsx subprocess (the Loader's own resolution environment) and asserts the exported plugin shape — this is what pins the `index.ts` forwarding entry, since it is exempt from typechecking.
- **Component specs** for the panel and host editor (real store engine, stubbed inject/locale) asserting navigation, picker focus handoff, solid editor surface, all allowlisted controls, live style/text preview, per-field reset, exact rollback, structured snapshots, acknowledgement/error/retry/clear states, and per-item removal.
- **Browser e2e** (`pnpm test:e2e`, Playwright Chromium against spawned services): panel open → proxied iframe renders → rich style/text preview → one-field reset → capsule/detail/marker echo → pending acknowledgement → **full send loop: the unchanged stock-composer user message is followed by one separate plugin Context message appended by `agent/pre-step`, the accepted user node consumes the capsule, and all temporary page mutations roll back** → clearing pending state before send produces no context. No fixed sleeps may stand in for acknowledgement boundaries. Keyless-by-design via the **configuration layer** (mirroring the harness scaffold): isolated `$DSH_HOME` with a pre-written welcome-notice acknowledgement (`settings.yaml`, exact version match), the provider key resolved through the product's own chain (repo `.env`, then `~/.dsh/.env` — without it a dead-loopback `DEEPSEEK_BASE_URL` makes the probe message fail instantly), the shipped `directory-picker-auto` row replaced by `-browse` (the auto chooser cannot resolve interactions headless), and `llm-deepseek` patched with `retryPolicy.maxRetries: 0` so turns settle without churn. Each scenario connects its own workspace directory so sessions never interfere.
- **`pnpm check`** is the repo gate (typecheck, unit suite, gen-config idempotence, bundle banner-id contract, build); `pnpm check --e2e` adds the browser suite. The harness's own suites (`test:gui`/`test:web`) are not run from this repo — the harness tree is untouched by design.
- Store-factory and component tests call `createWebviewStore().create()` directly — the sanctioned zero-machinery path; production code never calls the factory outside `apply`.

## Local development and verification

- **New plugin checkout/worktree bootstrap:**
  1. Ensure the external harness checkout is on the reviewed 0810 tag above. Keep it outside this repo and do not patch it for this plugin.
  2. If the package's absolute `link:` dependencies do not name that checkout, export `DSH_HARNESS=<absolute harness root>` before running repo scripts. Never rewrite them to worktree-relative paths.
  3. Run `pnpm install` in this repo. This installs the zero-dependency pre-commit hook through `prepare` and materializes the harness package links.
  4. Run `pnpm setup:harness`. It resolves the harness, installs/builds it only when its runtime artifacts are missing, and regenerates the gitignored `cordis.yml` plus `packages/dsh-web-review/entry-name.json` for this checkout's absolute path.
  5. Run `pnpm check` before development. For UI or send-path work, also run `pnpm test:e2e` (or the combined `pnpm check:e2e`). A copied `node_modules`, `cordis.yml`, or `entry-name.json` from another workspace is not valid bootstrap state.
- **New DSH workspace/session bootstrap:** start the target application's development server, start this plugin with `pnpm dev`, open the reported DSH URL, and connect the source directory the agent is allowed to edit. Give the assistant an absolute HTTP(S) URL for the running app; assistant-authored absolute links activate Preview. Preview only trusted development pages, because proxy content executes same-origin, and do not expect browser-cookie login flows or HMR WebSockets to work through the proxy.
- **Dev loop:** `pnpm dev` runs `dsh web --dev --port 3090 --patch ./cordis.yml` AND this package's tsdown watch together — both must run from the same places per the loading model above; neither alone updates the GUI. Browser refresh applies rebuilt client bundles; node-half changes require restarting the web process (cordis HMR is disabled for web). `pnpm demo` serves the demo page (default port 5173).
- **Manual acceptance reuses the user's profile:** the acceptance `pnpm dev` launch must leave `DSH_HOME` unset unless the user explicitly requests isolation. It therefore reuses the user's normal DSH profile, settings, providers, and product bundle; the generated `cordis.yml` may add only the single absolute-path `dsh-web-review` insert row through `--patch`. Never present an isolated test profile as the user's acceptance instance. Isolated temporary `DSH_HOME` directories remain required for automated E2E and are allowed for an explicitly identified concurrent-worktree diagnostic launch.
- **Preview before final verification:** after implementing a user-visible change, start a real preview service when practical and give the user its clickable DSH URL (plus the demo URL when relevant) so they can inspect the result while automated validation continues. Keep the service alive during acceptance. In a worktree, never assume the default `3090`/`5173` ports are available: probe for unused ports, launch with worktree-specific values such as `DSH_WEB_PORT=<free-port> pnpm dev` and `DEMO_PORT=<free-port> pnpm demo`, regenerate the overlay from that worktree, and do not stop or reuse another checkout's processes. Report the exact URLs, profile posture, and process ownership in the handoff.
- **Credential continuity for isolated previews:** when automated E2E or an explicitly requested diagnostic launch uses an isolated `DSH_HOME`, the isolation must not silently make a user's already-configured provider unavailable. Preserve DSH's credential precedence without exposing secret values: inherit an existing provider environment variable first; otherwise, when the key is stored by DSH, copy the default `~/.dsh/.credentials.yaml` into the temporary `DSH_HOME` with mode `0600`; retain `~/.dsh/.env` only as the product's read-only fallback. Never print, parse into tool output, commit, or embed credentials in Cordis YAML, shell arguments, screenshots, or logs. Remove temporary credential copies when the preview service stops. If no configured credential exists, say so explicitly instead of presenting a keyless screenshot session as a fully verified model loop.
- **Verification ladder:** `pnpm check` (typecheck + unit + config/bundle contracts + build) → `pnpm test:e2e` (browser suite; also `pnpm check --e2e`) → manual acceptance. The pre-commit hook runs the fast subset automatically.
- The running 3080 GUI is served from the harness snapshot checkout and is NOT touched by this plugin's dev loop.
- End-to-end acceptance: open a page through the proxy → pick elements → comment → send → model edits workspace source → manual iframe refresh shows the change.
