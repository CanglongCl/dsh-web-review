# AGENTS.md — dsh-web-review (webview panel + element annotation)

Rules for the dsh-web-review plugin: the webui's right-side page-preview panel, in-iframe element selection and commenting, and the AI collaboration loop that turns annotations into workspace source edits.

**This plugin lives OUTSIDE the harness checkout** — it is developed in the user's own repo (dsh-web-review) and loaded into a `dsh web` instance by a launch overlay, with zero modifications to the deepseek-harness source tree. Resolve the active harness root with `scripts/harness-path.ts` (or `DSH_HARNESS`), then read `<harness>/packages/client/AGENTS.md`, `<harness>/.agents/notes/implemented/architecture/2026-07-22-slot-type-chain-implementation.md`, and `<harness>/AGENTS.md` before touching slots, stores, or inject faces. Relative links to an assumed sibling checkout are forbidden because they resolve incorrectly from Codex worktrees.

## Loading model (why development uses a profile-local package alias)

- `dsh web` boots the `web` profile's ordered bundle layers and applies each `--patch` file after the profile/user layers. The Loader and client-modules resolve package names from the profile composition anchor, which does not contain this external checkout.
- Harness 0812's built CLI uses native ESM. Its Loader normalizes an absolute path to a `file:` URL, and Node rejects directory imports; the old absolute-directory plus root `index.ts` channel is invalid. A file path would load the node half but still break client-modules' independent `<name>/package.json` scan.
- Development instead uses the bare alias `@dsh-web-review-dev/plugin`. Before Web boot, `scripts/profile-plugin-link.ts` creates or repairs exactly one symlink at `$DSH_HOME/profiles/web/node_modules/@dsh-web-review-dev/plugin` pointing to this checkout's package directory. Loader import and client-modules manifest scanning then use ordinary package resolution from the profile anchor. A non-symlink at that alias is never replaced.
- The launch overlay (`cordis.yml`) inserts one row: `- insert: - { id: dsh-web-review, name: '@dsh-web-review-dev/plugin' }`. The **tsdown client-bundle banner id must equal the entry name** (`__ModuleLoader__.load({ id: ... })` is checked against the boot-graph row id by `arrive()`); `scripts/development-entry.ts` is the source shared by generated `entry-name.json`, `cordis.yml`, and the profile-link materializer.
- **Official profile-bundle publication is separate from the source-checkout dev channel.** `lib/client.js` keeps the development alias id required by the external `--patch` overlay. The same source builds `lib/client-official.js` with the stable private package id `@canglongcl/dsh-web-review`; `pnpm package:official` stages that artifact in a prebuilt tarball whose manifest declares `dsh.bundle.patch`. Do not reuse one client artifact for both ids.
- The generated `dist/package/` allowlist is exact: package manifest, `cordis.patch.yml`, self-contained `lib/index.js`, `lib/client-official.js` plus its map, the isolated-frame `lib/bridge.js` plus its map, the Chinese and English root READMEs, their two screenshot assets, and their GIF demo. Source, `.git`, `node_modules`, the profile-local development link/configuration, and the development-channel client bundle must never enter the official package.
- The built node half must stay **self-contained**: the Loader imports the external package from its own directory, which must not require a local `node_modules`. Small DSH construction helpers (`createUserMessage`, `SessionId`) may be value-imported in source only when tsdown inlines them into `lib/index.js`; a surviving bare runtime import is a load-order regression.
- HMR: the repo's `pnpm run dev:web` watch scans only harness `packages/*/*`; the external bundle is watched by the package's OWN tsdown watch (`pnpm run build:watch`). The 0812 Web profile mounts its HMR receiver unconditionally and broadcasts rebuilt frames regardless of who rewrote the served bundle; there is no `--dev` Web flag.

## Isolated Preview transport

- **Control plane:** the DSH host exposes exact `POST | DELETE /webview-preview-sessions`. It requires same-origin browser `Origin`, JSON, and the plugin client header; it has no CORS grant. `POST { target }` accepts any credential-free absolute HTTP(S) URL and returns a strict `{ sessionId, frameUrl, frameOrigin, targetOrigin, channel }`. `targetOrigin` must match the entry target encoded in `frameUrl` and bounds accepted ready-page URLs. `DELETE { sessionIds }` revokes capabilities. No target bytes are served from the DSH host Origin, and the legacy `/webview-proxy` host route must not return.
- **Origin boundary:** the node face starts a separate server bound to `127.0.0.1` on an ephemeral port. Every top-level target gets a random 128-bit `<session>.localhost:<port>` Origin, distinct from DSH and every other preview. Sessions expire, are capped, and are revoked on frame disposal. The iframe is sandboxed but keeps `allow-scripts allow-same-origin` because the random Origin itself is the isolation boundary.
- **Target binding and rebinding defense:** a session accepts requests only for its normalized target Origin. The first DNS resolution is pinned for the session; native HTTP(S) requests retain the original Host/SNI while connecting only to those addresses. Same-Origin redirects stay in the session. Cross-Origin markup navigation or redirects create a new random session through a bounded server-authored handoff document. Never replace this with an open redirect/fetch endpoint or reuse a Preview Origin across target Origins.
- **Transport limits:** only GET/HEAD/POST are forwarded; request/response bodies are capped at 10MB, upstream work times out around 15s, redirect count and cross-Origin handoff depth/fanout are bounded, and browser cookies/authorization are never forwarded. Upstream cookies, framing/CSP, connection, reporting, and host-mutating headers are stripped; HTML receives the plugin-owned exact-parent `frame-ancestors` policy. The handler cancels streams as soon as a cap is crossed.
- **HTML rewriting:** use `parse5`; no regex-over-HTML. Remove CSP/refresh meta directives and inject, before page-authored scripts, the proxy `<base>`, frozen bridge bootstrap config, and `bridge.js`. Same-target-Origin URL-bearing attributes (`href | src | action | srcset | poster | data-src`) stay on the isolated proxy; cross-Origin static `href`/`action` values use the handoff route, while cross-Origin POST forms are rejected. Cross-Origin subresources retain browser-native CORS. Query-only references are promoted into the encoded target, root-relative runtime requests map to the bound target Origin, and same-Origin POST forms forward exact bytes.
- **Build boundary:** `src/bridge/index.ts` has its own TypeScript project and tsdown IIFE output. Both source-development and official packages use the same generic bridge artifact; unlike the client bundles, it contains no package-loader banner id.

## Picker and bridge contract

- **No direct frame access:** production host code must never read `iframe.contentDocument`, call page functions, retain `Element` references, or infer safety from a successful cross-frame read. The parent talks only to the exact `iframe.contentWindow` at the descriptor's exact Origin, target Origin, protocol version, and random channel. Page-reported URL Origins must equal the server-bound `targetOrigin`; handoffs are accepted only from the current expected frame identity.
- **Bridge ownership:** `src/bridge/index.ts` captures the native parent messaging primitive before page scripts, deletes its bootstrap global, installs picker style/behavior, and owns all live DOM handles and rollback ledgers. Host commands are an explicit discriminated union; frame responses/events are strictly decoded and bounded in `preview-contract.ts`. The channel routes one session but is not a claim that page evidence is truthful: page URL/title/DOM metadata remain untrusted.
- **Serializable editor protocol:** the host receives bounded snapshots, geometry, navigation availability, and serialized tree nodes. It sends opaque handles for select/navigate/style/text/commit/cancel operations. Comments never enter the frame. The solid editor remains a host React overlay, so page opacity, transforms, fonts, and stacking contexts cannot affect it.
- **Picker behavior:** hover highlights the deepest element under the pointer; in pick mode a click on an unannotated element hands it to `onPick` (the parent opens the host editor); a click on an already-annotated element or its marker hands the pick id to `onMarkClick` (re-open that editor). Clicks never navigate (`preventDefault`). The numbered marker circles are the only injected chrome and reposition on scroll/resize. Esc with no editor transaction or a second toggle deactivates pick mode.
- **cssPath:** delegated to `css-selector-generator` (inlined into the bridge artifact) with the priority `['id', 'class', 'tag', 'nthoftype']` — order is priority, output is the shortest unique selector, so index segments appear only when uniqueness requires them; `null` falls back to the bare tag.
- **Snapshot fields** (exact keys, mapped to the wire shape by `annotation-snapshot.ts`): `tagName`, `id`, `className`, `cssPath` (shortest unique selector — runtime anchor for marker rebuilds), `fullPath` (complete ancestor chain), `label` (accessible label), `role` (explicit/implicit ARIA role), `stableClasses` (semantic classes; utility/variant tokens and fully opaque hashes filtered, but `<hash>_<name>` CSS-module classes are kept for their searchable semantic suffix), `inToolChrome` (true when the element sits inside this plugin's own `[data-webview-ui]` chrome, e.g. dogfooding a DSH Web GUI), `anchor` (framework source anchor or null), `outerHTML` (≤1500 chars), `textContent` (≤300 chars, crossing the node wire for unlabeled targets), `rect`, computed `display/position/font-size/color/background-color/margin/padding/width/height`. Caps are contract — enforce at capture and at the node wire boundary, and test exact limits. The source anchor comes from `source-anchor.ts`: framework-agnostic probing of React fiber `_debugSource`, Vue `__file`, and Svelte `__svelte_meta` (defensive reads, null in production builds/unknown frameworks).
- **The page always loads through a random Preview Origin** — there is no direct remote iframe fallback. Element picking is available only after the exact-Origin bridge handshake; login/origin-gated pages may fail to render (see Known limitations).

## Annotation message and AI collaboration

- **Structured wire, node-owned text.** The browser POSTs exact-shape `{ sessionId, page, comments[] }`, never XML/Markdown. Each comment carries bounded `changes[]`, nullable `textChange`, and edit-time `viewport`; only changed values cross the boundary and every non-empty comment must contain user intent. User-authored values fail visibly instead of being silently truncated. `annotation-contract.ts` pins request/count/field/context caps; `annotation-context.ts` strictly validates object keys, the credential-free HTTP(S) page policy, the shared property allowlist, and is the single assembly point. Malformed, oversized, duplicate, wrong-content-type, and unknown-session requests fail visibly.
- **Stable Browser Comments format.** The context is English regardless of UI locale and starts with `# Browser comments`. Each full snapshot says it supersedes earlier snapshots. Page/target/original-value metadata is explicitly untrusted page evidence; comments, requested values, and text replacements are user-authored input. The target block carries `Target owner:` when `inToolChrome` is true (the element belongs to this plugin's own nested chrome, so the edit lands in this plugin's source, not the previewed page) and `Target text:` (bounded `textContent`) when the element has no accessible label. The optional `Browser annotation` block includes viewport plus `property: before -> after` lines. Raw outerHTML, full computed styles, rectangles, editor state, and screenshots are excluded.
- **Send-time context path.** The node face resolves the live branded `SessionId` and stores one deduplicated pending full snapshot. Its `agent/pre-step` listener delegates with `next()`, preserves `reject`, and on `enter` appends one user-role message with `{ kind: 'plugin', plugin: 'dsh-web-review' }` after the returned messages; it never rewrites claimed message content. The exact plugin `user/message` session event consumes the matching pending snapshot, so a rejected/aborted admission cannot lose it and a newer concurrent snapshot cannot be cleared by an older event. Clearing before send removes pending state and injects nothing; `agent/disposed` releases state.
- **Stock input machine remains authoritative for drafts.** Annotation mode adds a dedicated Send button, enabled only after a non-empty snapshot is acknowledged with a node-issued `snapshotId`. With a non-blank composer draft it calls the public `inputActions.submit()` action, so ordinary serialization, queueing, failure handling, and successful draft clearing remain stock behavior; the plugin never reads or sends a second copy of that text. Only the durable plugin Context record carrying that exact id clears the dock; generic/older human records cannot acknowledge a newer snapshot. The stock machine deliberately rejects an empty draft, so the no-draft arm calls the scoped public `conversation.send` with the localized fixed request (“请根据页面批注修改前端实现。”). Failures keep annotations visible and retryable.
- **No model-facing tool is added:** the context is a logged user-role plugin message; the model acts with existing workspace tools (`tool-fs`, bash). Adding a tool requires a consumer that proves the message form insufficient.
- The AI's workspace is the session's workspace root — the dev instance is launched with `cwd` = the user's project directory (or the GUI workspace picker), so `tool-fs` edits land in the project the iframe previews.

## UI discipline

- Follow the four props shares, the store-factory rule, and the data-access ladder (upstream client rules): business state (url, picks, comments, pick mode, panel open/width/split) lives in `createWebviewStore()` declared at register. Components receive everything through props — no ctx, no React contexts, no hand-made hooks.
- **Assistant-link delegation:** the always-mounted annotation dock owns one document capture-phase listener, including while it renders no capsule. It intercepts only unmodified left-clicks on credential-free absolute HTTP(S) anchors inside Harness 0812's `[data-chat-flow-kind="assistant-step"]`; user/tool/modifier/middle clicks and `[data-webview-ui]` chrome keep their normal behavior. The injected dock callback normalizes the URL, writes it through the plugin store actions, clears stale picks, closes Details through `ctx.layout`, and activates Preview.
- **Model guidance:** the node face contributes the reviewed, locale-independent `plugin:dsh-web-review-preview` system section at order `-97`. It states the capability and review loop: emit an absolute HTTP(S) Markdown link for a page worth reviewing (and verify a local development server when source edits are expected), then let the user annotate it in Preview.
- The preview has two chrome states. Browse mode is the URL row with an inline external-open action plus separate refresh and comment-bubble actions. Annotation mode replaces it with the light-blue toolbar: exit, clear, centered current URL, and the counted Send button. The selected element gets a solid-white host editor: collapsed comment pill first, a Select-triggered serialized DOM hierarchy tree, and an Adjust-triggered Figma-style inspector for the shared visual-property allowlist and safe direct-text editing. Select and Adjust are mutually exclusive. The selector moves to the first child, parent, previous sibling, or next sibling from one compact four-button row labeled 子级/父级/上一个/下一个 (Child/Parent/Previous/Next); each button carries a small trailing shortcut keycap instead of a redundant direction icon. The normal pick flow focuses the host-owned canvas surface, where Enter, Backslash, Shift+Tab, and Tab issue the same bridge movements without exposing those host events to page listeners. Whenever the tree is closed, a compact current-target bar remains below the comment input; each successful shortcut replaces its target text with a short directional transition, boundaries leave it unchanged, and reduced-motion removes directional movement. Host toolbar buttons and editor inputs keep native behavior. The bridge owns a page-side capture fallback when the iframe is explicitly refocused, while editable page controls retain native keys. Switching targets restores the previous element's transaction preview, preserves the comment draft, and never carries its style/text diffs to the new target. The editor prefers a clear region above/below the selected target, shrinks its scrollable body before overlap, then tries a clear horizontal side on wide frames; overlap is allowed only when a large target leaves no usable region. Changed rows expose individual reset actions. The composer dock renders ONE compact capsule (count + sync state + clear), not one chip per pick. Hover or focus opens a light detail card above it; row click re-opens the same host editor.
- Live element references and rollback ledgers live only in bridge-private maps/weak maps, never in React, the store, or message payloads. Before the first temporary preview write, record the exact inline value and priority; text edits are limited to one direct text node. Reset, Cancel, remove, clear, successful send, navigation, and unmount must restore the exact original DOM state. Remaining picks re-anchor by cssPath and replay committed preview values after frame reload.

## Known limitations (do not "fix" into breakage)

- **Preview Origin isolates capabilities, not truth.** Arbitrary HTTP(S) page scripts execute on a random Origin and cannot obtain DSH same-origin access. They can still influence their own DOM and therefore all page URL/title/selector/anchor/snapshot fields remain untrusted evidence. Only bounded user-entered comments and requested values are treated as user intent.
- **Annotation preparation and stock-composer Send are not atomic.** The public browser input service has no general pre-submit transaction. The capsule exposes preparing/ready/error; users must wait for “发送时注入”. The pre-step waterfall appends one separately sourced message only after delegating to `next()` and receiving `enter`; claimed-message rewriting and delay-based race hiding remain forbidden.
- **Absolute URLs hardcoded in page JS** (for example `fetch('https://origin/api')`) and WebSocket endpoints are not rewritten. Plain-relative calls resolve through `<base>` and root-relative HTTP requests map to the session's bound target Origin. Do not rewrite JavaScript source to disguise this limitation.
- **Dev-server HMR websockets** do not survive the proxy; the page renders but live-reload is absent.
- **Server-side fetch carries no browser cookies** — login-gated, original-Origin-enforcing, client-certificate, and anti-bot pages may not render. There is no unsafe direct-mode fallback.
- **Programmatic cross-Origin location assignment can leave the bridge.** Rewritten static markup navigation and server redirects use handoffs, but dynamically created links or arbitrary page JavaScript can still replace the iframe location directly. The host must fail closed (picker unavailable), never fall back to direct DOM access.
- **The development alias is profile-local state**: moving or switching the repo is handled by the next `pnpm dev`, E2E, or acceptance launch repairing its exact symlink. If a real file or directory occupies the reserved alias, launch fails instead of replacing it.
- These are documented for users in the package README (Known Limitations section) and in panel hints; changing them needs a consumer-driven design.
